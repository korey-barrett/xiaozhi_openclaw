# XiaoZhi ESP32 Channel Integration Guide

This guide explains how to connect the XiaoZhi WebSocket Channel in an OpenClaw Gateway (current npm package: `@xiaozhi_openclaw/xiaozhi@0.0.6`).

## Contents

## Prerequisites

- Node.js `18+`
- The OpenClaw Gateway can start normally
- xiaozhi-esp32-server-golang exposes a WebSocket endpoint (e.g. `/ws/openclaw`)
- You have a valid JWT token (recommended: generated by the XiaoZhi server's openclaw-endpoint)

## Installation

### Install with the OpenClaw plugin command (recommended)

Run this from any directory:

```bash
openclaw plugins install @xiaozhi_openclaw/xiaozhi
```

To pin a version:

```bash
openclaw plugins install @xiaozhi_openclaw/xiaozhi@0.0.6
```

Compatibility note: with OpenClaw `2026.3.8+`, use `@xiaozhi_openclaw/xiaozhi@0.0.6`.

If you hit `clawhub` rate limiting, install directly from the current npm package directory in installer mode:

```bash
npx -y @xiaozhi_openclaw/xiaozhi@0.0.6 install
```

If you previously copied the directory manually to `~/.openclaw/extensions/xiaozhi`, clean up the old directory before reinstalling:

```bash
openclaw plugins uninstall xiaozhi
rm -rf ~/.openclaw/extensions/xiaozhi
```

If `openclaw plugins uninstall xiaozhi` reports that the plugin is not a managed installation, just delete the directory.

After installation, check:

```bash
openclaw plugins list
openclaw channels capabilities --channel xiaozhi
```

If `openclaw channels capabilities --channel xiaozhi` fails, first run:

```bash
node /path/to/openclaw-channel/cli.mjs doctor
```

This self-check prints the actual `openclaw` executable path it invokes and checks both `plugins list` and `channels capabilities --channel xiaozhi`. If the plugin appears in `plugins list` but capabilities still fail, you are usually running a different OpenClaw binary, or the plugin failed during load.

During development, if you want to load the local source directory directly instead of copying it to `~/.openclaw/extensions`, use `--link`:

```bash
openclaw plugins install --link ./openclaw-channel
```

`--link` only supports local paths. After code changes, you usually only need to restart the gateway; reinstallation is not required.

After installation, prefer the official OpenClaw `config set` commands to write the `channels.xiaozhi` configuration:

```bash
openclaw config set channels.xiaozhi.enabled true --strict-json
openclaw config set channels.xiaozhi.url "ws://localhost:8080/ws/openclaw"
openclaw config set channels.xiaozhi.token "<jwt>"
```

To add a named account:

```bash
openclaw config set channels.xiaozhi.enabled true --strict-json
openclaw config set channels.xiaozhi.accounts.office.enabled true --strict-json
openclaw config set channels.xiaozhi.accounts.office.name "Office"
openclaw config set channels.xiaozhi.accounts.office.url "ws://localhost:8080/ws/openclaw"
openclaw config set channels.xiaozhi.accounts.office.token "<jwt>"
openclaw config set channels.xiaozhi.defaultAccount "office"
```

Note: OpenClaw `2026.3.23-1`'s `channels add` subcommand does not preload the plugin registry for external channel plugins, so a local/external channel like `xiaozhi` may still report `Unknown channel: xiaozhi` when you run `openclaw channels add --channel xiaozhi ...`, even if it is already `loaded`.

## Configuration

Edit the OpenClaw configuration file (e.g. `~/.openclaw/openclaw.json`):

```json
{
  "channels": {
    "xiaozhi": {
      "enabled": true,
      "url": "ws://localhost:8080/ws/openclaw",
      "token": "your-jwt-token",
      "reconnectInterval": 5000,
      "heartbeatInterval": 30000,
      "heartbeatTimeout": 10000,
      "accounts": {
        "default": {
          "enabled": true,
          "url": "ws://localhost:8080/ws/openclaw",
          "token": "your-jwt-token"
        }
      },
      "defaultAccount": "default"
    }
  }
}
```

Parameter descriptions:

- `reconnectInterval`: reconnect interval, default `5000` milliseconds
- `heartbeatInterval`: heartbeat send interval, default `30000` milliseconds
- `heartbeatTimeout`: single heartbeat timeout, default `10000` milliseconds

### Token Generation (optional)

To generate a temporary token, use the repository script:

```bash
cd /path/to/xiaozhi_openclaw
node generate-token.js <user_id_number> <agent_id> <endpoint_id> [expires_in]
```

Example:

```bash
node generate-token.js 1 main agent_main
```

## Start

1. Start xiaozhi-esp32-server-golang:

```bash
./xiaozhi-server --config config.yaml
```

2. Start the OpenClaw Gateway:

```bash
openclaw gateway start
```

## Verification

### 1. Check Status

```bash
openclaw status
```

Expected:

```text
Channels:
  xiaozhi (default):
    Status: running
    URL: ws://localhost:8080/ws/openclaw
```

### 2. View Logs

```bash
openclaw gateway logs --follow
```

Expected to include:

```text
[xiaozhi:default] connecting to ws://localhost:8080/ws/openclaw
[xiaozhi:default] connected
[xiaozhi:default] received handshake_ack ...
```

### 3. Verify Automatic Reconnect

When the peer service restarts or the network drops briefly, the log should show:

```text
[xiaozhi:default] scheduleReconnect called ...
[xiaozhi:default] reconnecting...
```

Note: the current implementation has reconnect fallbacks for both `onclose` and the case where `onerror` fires without a following `close`.

## Troubleshooting

### 1. `Cannot find module 'ws'`

Cause: the runtime environment lacks a WebSocket implementation.

Fix:

```bash
npm install ws
```

Note: the plugin prefers the `ws` package and falls back to the global `WebSocket` if `ws` is not installed.

### 2. No reconnect after `websocket error`

The current version handles this scenario; if it still occurs, verify:

- whether `scheduleReconnect called` appears in the log
- whether `reconnectInterval` is too large
- whether the gateway process is still alive

If `undici` appears in the log stack, the runtime is using Node's built-in global `WebSocket`. With some servers this implementation reports `onerror readyState=0`, but switching to `ws` allows the handshake to succeed. The current repository version prefers `ws`; publish and upgrade the plugin, then retry.

### 3. `Unsupported schema node. Use Raw mode.`

This is an admin UI schema rendering compatibility issue. The current plugin uses a flat configuration schema; upgrade the plugin and restart the gateway, then retry.

### 4. `Cannot find module 'openclaw/plugin-sdk/core'`

This happens when an older package loaded as an external plugin from `~/.openclaw/extensions/xiaozhi` fails to resolve the host SDK at runtime. `0.0.5+` removes these runtime bare imports; upgrade and retry.

If the installer also reports `plugin already exists`, delete the old directory and rerun the install command.

### 5. `ClawHub ... 429: Rate limit exceeded`

Switch to installer mode directly:

```bash
npx -y @xiaozhi_openclaw/xiaozhi@0.0.6 install
```

This command performs a local install from the current npm package directory and no longer relies on `clawhub` to fetch the plugin package.

### 6. `Unknown channel: xiaozhi`

First run:

```bash
openclaw plugins list
openclaw plugins doctor
openclaw channels capabilities --channel xiaozhi
node /path/to/openclaw-channel/cli.mjs doctor
```

Focus on two things:

- whether `xiaozhi` appears in `plugins list`
- whether `channels capabilities --channel xiaozhi` succeeds

If the former succeeds and the latter fails, first check:

- whether the `openclaw` actually running in the current shell is a different binary
- whether the plugin throws during load

If only `openclaw channels add --channel xiaozhi ...` fails while `channels capabilities --channel xiaozhi` succeeds, switch to:

```bash
openclaw config set channels.xiaozhi.enabled true --strict-json
openclaw config set channels.xiaozhi.url "ws://localhost:8080/ws/openclaw"
openclaw config set channels.xiaozhi.token "<jwt>"
```

If you explicitly do not want to write multiple `config set` commands by hand, you can still use `node /path/to/openclaw-channel/cli.mjs setup ...` as a fallback; however, the official OpenClaw `config set` commands are preferred.

### 7. Authentication Failure

Check:

- whether the token has expired
- whether the token's signing secret matches the server
- whether the token claims satisfy server validation
